# Личное развитие и общая жизнь

Реализация решений владельца от 2026-09-05. Связанные [решения](PRODUCT_DECISIONS.md), [экономика](ECONOMY_UPDATE.md), [вход](ENTRY_AND_PAIRING_UPDATE.md), [знакомства](MATCHING_PRODUCT_UPDATE.md).

## Библиотека и личный прогресс

`/development` доступен одиночке и участнику пары. Каталог `src/domain/model/development/catalog.ts`: 8 рефлексивных анкет, 19 личных практик, 18 совместных практик, 30 разговорных тем, 30 идей отдыха, 3 программы. Из них одна дополнительная анкета и один сценарий открываются через магазин; бесплатный набор содержит 7 анкет и 18 личных практик.

Шесть областей: communication, domestic, personalViews, finance, sexuality, psyche. Связь с техническими Factor domains указана отдельно; финансовые и интимные предпочтения не получают выдуманного измерения. Статус всех материалов `DEMO_SELF_REFLECTION`. Прохождения не создают Factor evidence, не меняют matching и не считаются доказанным ростом навыка. Предложение следующей личной практики опирается на явный собственный самоотчёт или объясняет недостаток данных. Каталог можно расширять; перед научной публикацией нужны проверенные методика, источник, интерпретация и права.

Один `DevelopmentRun` на owner/Pair + content + revision + неделю UTC. `_id` детерминирован, контекст Pair канонизируется после resource guard. В run только участники и факт выполнения; ответы и заметка — в отдельном immutable `DevelopmentCompletion` владельца. Каждый вопрос имеет явный ответ или skip; отсутствие ответа не заменяется нейтральным. Общий статус `PARTIAL` после одного и `COMPLETED` после обоих. Тексты второго участника не раскрываются. Повтор с тем же результатом безопасен, иной результат для уже завершённого run возвращает 409.

Опубликованная первая редакция сохранена в `src/domain/model/development/published/v1.ts`. Типизированный repository в `publications.ts` хранит материал вместе с формулировками шкалы ответов, запрещает повтор key/revision и замораживает публикации. Новую редакцию добавляют отдельной публикацией в `catalog.ts`, сохраняя прежнюю. Новый run использует latest revision; чтение и завершение существующего — строго его `contentRevision`, включая старые вопросы и варианты ответа. Отсутствующая версия возвращает `409 CONTENT_VERSION_UNAVAILABLE` без подстановки latest. Текущий доступ к Pair и дополнительному материалу проверяется раньше версии, а при записи повторяется внутри транзакции. Повтор завершения сохраняет результат, timestamp завершения и прежний ключ награды. Миграция DB и CMS не нужны.

На главной, личном экране «Сегодня» и странице пары есть переходы к сохранённым занятиям и начатым программам. `/development?run=<id>` открывает конкретный run после перезагрузки; `?program=<key>#programs` выделяет программу и ближайший незавершённый шаг. Overview отдельно выбирает до 30 незавершённых и до 30 завершённых доступных run: новые завершения не вытесняют незавершённые из списка. Набранные, но не отправленные ответы и заметки остаются только в памяти формы; после перезагрузки они не восстанавливаются. Сохранённый результат загружается с сервера.

Обновление ограничено явными кнопками и возвращением фокуса/видимости страницы с интервалом не менее 15 секунд и без параллельных автоматических запросов. Фонового polling/WebSocket нет. Открытая форма сохраняет локальный ввод; общую запись при конфликте пользователь сверяет с текущей версией перед повторной отправкой. Ошибка доступа скрывает ранее загруженные закрытые данные и действия.

Полный список незавершённых занятий на `/development` загружается отдельно, по 30 записей кнопкой «Показать ещё». Сортировка сервера — `createdAt DESC, _id DESC`, курсор задаёт позицию; новые записи появляются после обновления с первой страницы. Каждая страница повторно проверяет пользователя, текущие active/paused Pair и доступ к дополнительному контенту. Смена этого контекста возвращает `409 RUN_LIST_CHANGED`: клиент удаляет накопленные страницы и читает первую заново. Обычная сетевая ошибка оставляет строки и возможность повторить запрос; запоздавшая страница после обновления игнорируется. Главная и «Сегодня» продолжают использовать ограниченный overview и переход в полный список.

Награды: анкета — один раз на материал/ревизию; личная практика — раз в неделю; практика пары — обоим после двух отметок. Тип впечатления и skip не меняют награду. Темы/досуг не создают бесконечный источник монет. Ограничения кошелька действуют дополнительно.

| API | Контракт |
| --- | --- |
| `GET /api/development` | Карточки без prompts/steps, доступ, собственный прогресс, программы, предложение шага; `recent` содержит до 30 незавершённых и до 30 завершённых доступных run. |
| `GET /api/development/runs?cursor=` | `{runs: DevelopmentRunDTO[], nextCursor: string \| null}`: до 30 доступных `ACTIVE`/`PARTIAL` run. Начальная страница без query; продолжение только с выданным opaque cursor. Другие параметры запрещены. Неверный cursor — 400, смена scope — `409 RUN_LIST_CHANGED`. Cursor не является разрешением доступа; ответы/заметки в DTO отсутствуют. |
| `POST /api/development/start` | `{contentKey,pairId?}` → `{runId}`. Совместные форматы требуют активную Pair. |
| `GET /api/development/runs/:id` | Закреплённая редакция материала и шкалы, относительные статусы и только собственный результат. |
| `POST /api/development/complete` | `{runId,answers:[{question,value:0..3|null}],feedback,privateNote?}` → `{runId}`. |

POST требует сессию, JSON и Idempotency-Key. Перед replay проверяется текущий доступ. Cache хранит receipt без ответов; клиент делает guarded GET после POST. Hash тела не является разрешением доступа.

## Общая жизнь

`/shared-life` использует одно bounded пространство `PairWorkspace` на канонический Pair id. До 300 записей и 50 metadata изменений. Допустимы `EVENT`, `TASK`, `SHOPPING`, `GOAL`, `BUDGET`, `MEMORY`; строгие разные формы исключают произвольные поля. Оба участника могут править общие записи. Авторство отображается относительно текущего пользователя. Пауза разрешает просмотр, окончание пары закрывает пространство; новый Pair получает новое пространство.

- Даты и события: локальные YYYY-MM-DD; недельные/месячные/годовые повторения сохраняют исходный календарный якорь (31 января → 28 февраля → 31 марта). Выполненное повторение пропускается через `lastCompletedDate`; годовщина задаётся людьми.
- Задачи: ответственный, дата, повторение, планируемое время включая организацию. Сумма минут — ручной план, не оценка справедливости.
- Покупки/желания: количество, взято на себя, выполнено. Внешнего бронирования/оплаты нет.
- Цели: ответственный за цель и до 20 этапов с отдельными отметками.
- Бюджет: целые минимальные единицы, доход/расход/взнос, отдельные итоги по каждой валюте. Монеты приложения и банковские операции не смешиваются.
- Воспоминания: дата, место, заметка, необязательная HTTPS-ссылка на фото; фото не загружается автоматически и остаётся на исходном сервисе. Отдельное хранилище медиа и карта пока не добавлены.

`GET /api/pairs/:id/shared-life?today=YYYY-MM-DD` отдаёт текущий DTO. `POST` с тем же query принимает `{action:SAVE,entryId:UUID,expectedRevision,data}`, `{action:DELETE,entryId,expectedRevision}` или `{action:SETTINGS,settings,expectedRevision}` и возвращает только `{pairId,revision}`. Клиент после receipt читает актуальный DTO. Дата интерфейса влияет только на календарное представление, не на timestamp или награду.

Settings: реальная дата начала отношений, календарные поводы, отдельно включаемые авторские предложения, срок выделения напоминаний и валюта по умолчанию. Напоминания сейчас внутри приложения, без фоновых push/email. Конфликт версий возвращает 409; stale форма не перезаписывает запись партнёра. Изменение Pair и пространства сериализовано через `lifecycleRevision` в Mongo transaction.

Эти же дата и настройки применяются к [существующему виджету событий пары](PAIR_EVENT_SETTINGS_UPDATE.md). Дата связывания аккаунтов не подменяет начало отношений. Выключенное предложение нельзя принять по старой карточке или через idempotency replay; уже принятая история сохраняется.

## Приватность и ограничения

Экспорт `productWorkspace` содержит до 500 собственных результатов (с флагом truncation) и доступные текущие общие пространства. Чужие рефлексивные ответы исключены. Account cleanup удаляет owner completions/runs и общий workspace недоступной Pair; старые кеши shared-life удаляются по связанным Pair независимо от регистра пути. Новая recovery-логика удаления и архив расставания не реализовывались.

UI использует существующие стили. Главная, профиль пары и магазин ведут к новым разделам. `scripts/release-preflight.ts` включает новые модели для обнаружения/создания только добавочных индексов; production автоматически не менялся.

## Проверки

`npm run selfcheck:product-workspace`: покрытие каталога, явные пропуски, строгие формы, даты/високосность/месячный якорь, отдельные валюты, DTO и Mongoose schema.

`npm run integration:product-workspace`: разрешён только явно заданный локальный replica set и имя БД `_test`. Настоящие Mongo transactions: конкурентные первые открытия и завершения, однократные награды, partial/final пары, paywall403, чужой actor404, lowercase/uppercase идентичность, конфликт правок, экспорт без peer notes, опубликованные/отсутствующие версии, pause/end. Настоящие API handlers с session JWT дополнительно проверяют receipt-only cache и отказ replay после паузы. Скрипт очищает только свои UUID fixtures. Текущие результаты и воспроизводимые сценарии — в [приёмке двух пользователей](TWO_USER_ACCEPTANCE.md).
