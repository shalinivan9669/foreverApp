# События пары и настройки общей жизни — 2026-09-05

PairEventsPanel использует те же настройки пары, что и общая жизнь. Формат успешных API ответов и MongoDB schema событий не меняются.

- Дата создания Pair означает связь аккаунтов в приложении. Она больше не создаёт «первый месяц вместе», три/шесть месяцев или годовщину. Без корректной вручную введённой `PairWorkspace.settings.relationshipStartDate` такие предложения отсутствуют.
- Все памятные сроки считаются от этой календарной даты. Используется общая календарная функция: 31 января + месяц → 28/29 февраля, годовщина 29 февраля в обычном году → 28 февраля.
- `holidaysEnabled=false` выключает календарные предложения PairEvents. `authorEventsEnabled` управляет авторскими поводами в SharedLife; существующий реестр PairEvent не содержит отдельного авторского источника, новые авторские события здесь не добавлены. Поведенческие предложения по уже разрешённой общей сводке не считаются праздниками и сохраняют прежние правила.
- Refresh читает настройки **внутри транзакции после Pair lifecycle fence**. Изменение настроек из SharedLife использует тот же Pair fence: заранее рассчитанный контекст не может восстановить выключенные события после конкурентного изменения настроек.
- Несовместимые `upcoming`, `offered`, `snoozed` переходят в `expired`; неподходящие предложения не включаются в projection, включая `include=all`. Принятые/завершённые/отклонённые записи сохраняют исходный текст, источник и даты. Повторное построение кандидата не переписывает историю.
- Accept/decline/snooze проверяют актуальные настройки после транзакционного Pair guard. Старая карточка не принимается после выключения праздников или изменения даты, даже до refresh. Принятая историческая запись остаётся видимой, но повторный accept не создаёт эффектов, если её источник уже не соответствует настройкам.
- HTTP action route повторяет resource/lifecycle/settings access check **до** `withIdempotency`, включая replay сохранённого ответа. Канонический Pair/event ID используется в ключе route. Кеш команды не обходит новые настройки или завершение пары.
- Изменения не добавляют новые Factor targets и не читают private safety/profile/answers. Остаются текущая версия Factor registry, ограничения privacyClass и качественная общая weekly projection только после достаточных данных обоих. DTO по-прежнему не выдаёт внутренний source, factor keys или ответы.
