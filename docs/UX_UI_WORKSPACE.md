# Библиотека и общая жизнь: UX/UI, 2026-09-07

Реализованные UI-этапы 6 и 8 из [плана](UX_UI_IMPLEMENTATION_PLAN.md). Классификация каждого потока — `FEATURE_CHANGE`. Основные [контракты библиотеки и общей жизни](PRODUCT_WORKSPACE_UPDATE.md) сохранены: API, схемы БД, версии публикаций, доступ и награды не изменены. Пользователь поручил выбрать удобную группировку библиотеки; общая навигация по приложению остаётся через существующее главное меню.

## Библиотека

- `/development` начинается с трёх продолжений. Полный список раскрывается через «Все начатые занятия»; внутри остаётся серверная пагинация по 30 и кнопка «Показать ещё». Фильтры каталога не обрезают сохранённые прохождения.
- Каталог разделён на «Для себя» и «Вместе», затем на форматы. Шесть областей доступны как дополнительный фильтр. Личные занятия доступны участнику пары. Совместный каталог можно просмотреть без активной пары; начало совместного прохождения сопровождается объяснением недоступности и переходом к связыванию/состоянию пары.
- `scope`, `format` и `area` — состояние представления в query страницы. Открытие и закрытие конкретного `run` сохраняет эти параметры, `content` и `program`; возврат из программы сохраняет `#programs`. Маршруты `/questionnaires`, `/development?run=…` и `/development?program=…#programs` продолжают работать.
- Программы представлены компактными раскрываемыми строками с количеством пройденных шагов; прямой переход раскрывает нужную программу. Порядок опубликованных шагов и открытие существующего прохождения сохранены.
- У результата есть отдельная читаемая форма, защита ввода во время сохранения и предупреждение при закрытии/переходе с несохранёнными ответами. Черновики остаются в памяти формы. Общий status и собственный результат сохраняют прежние partial/final/paused состояния; ответы партнёра не добавлены.

## Общая жизнь

- Первым открывается список дел с ответственными и планируемым временем. Отдельные разделы: покупки и желания, повестка с ближайшими датами, операции реального бюджета, цели с этапами, хронология воспоминаний.
- Открытые дела идут перед завершёнными; операции бюджета и воспоминания — от новых дат к старым. Каждая зона имеет конкретное действие создания и собственное пустое состояние.
- Покупки показывают количество и взявшего ответственность участника. У целей видны число выполненных этапов, progress и отдельные доступные отметки. Реальный бюджет явно отделён от монет приложения; доходы, взносы, расходы и остаток показаны по каждой валюте.
- Редактирование записи, настройки и подтверждение удаления используют общий `Dialog`: единая прокрутка содержимого, возвращение фокуса, Escape и блокировка закрытия при mutation. Изменения настроек теперь собираются в одну форму с явным сохранением.

## Одновременные правки

Форма удерживает revision, с которой была открыта. `409` вызывает только guarded GET актуального пространства: автоматической повторной mutation нет. Пока загрузка актуальной версии не завершилась, повторное действие блокируется. Ошибка остаётся видимой; `401/403/404` при таком GET убирают защищённый snapshot.

Текущая серверная запись показана рядом с редактируемым черновиком; на узком экране блоки идут вертикально. Сравнение включает все поля типов, в том числе этапы цели, исполнителя, сумму/валюту, дату, заметку и внешнюю ссылку. Черновик сохраняет стабильный React-ключ при появлении и закрытии сравнения. Повторное сохранение доступно после явного подтверждения сравнения. Служебные отметки выполнения и взятая на себя покупка сохраняются из подтверждённой актуальной версии; редактируемые поля остаются в черновике. Если запись удалена партнёром, интерфейс объясняет, что сохранение создаст её вновь.

Подтверждение удаления также фиксирует revision на момент открытия. После изменения пространства пользователь сначала видит и подтверждает актуальную запись, затем отдельно удаляет её. Настройки сравниваются с серверными значениями без потери выбранных черновых значений.

Подтверждённое окончание пары немедленно скрывает кэш общей жизни; пауза немедленно запрещает правки и закрывает формы, даже если workspace GET ещё не завершился. Библиотека аналогично убирает недоступное совместное прохождение при подтверждённой смене/окончании пары или ошибке доступа; личные занятия сохраняют доступность при отсутствии доступа к паре. Ошибка сессии `401` скрывает также защищённые списки библиотеки.

## Проверки

- Targeted ESLint UI, hook, viewmodels и двух selfcheck — успешно.
- `npm run check:types` — успешно после исправления TS-narrowing в дополнительной проверке.
- `npm run selfcheck:product-workspace` — успешно: публикации/версии, строгие формы, курсор, календарь, валюты и DTO.
- `npm run selfcheck:continuation-ui` — успешно: прежняя реальная hook-пагинация и гонки сохранены; добавлены конфликт revision, отсутствие автоматического retry и повторной mutation, смена пары при запоздавшем conflict GET, отзыв доступа во время GET.
- `npx tsx scripts/workspace-ui.selfcheck.ts` — успешно: личные/совместные фильтры, все 35 продолжений, сохранение query/deep links, сортировка без изменения snapshot, повестка, полный набор полей сравнения.

Общий build и итоговые agent checks фиксируются в итоговом отчёте реализации. DB-интеграции для новых серверных контрактов не добавлялись: серверные контракты и persistence-логика не менялись.

## Изоляция параллельных локальных прогонов

Приёмка обнаружила, что разные порты не разделяют cookie одинакового hostname. В локальном инструменте добавлен `--host-prefix` со строгим enum `vmeste` (по умолчанию), `vmeste-workspace`, `vmeste-matching`. Это ограниченное изменение tooling: серверы остаются на loopback; actor по-прежнему ровно `a`/`b`; произвольные host, actor или query для авторизации не принимаются. Prefix одинаково участвует в проверке child server argv, Host allowlist, health probe, bootstrap и redirect. Selfcheck проверяет невалидные prefixes, перекрёстные actor/host/port и query; targeted ESLint и typecheck прошли. Публичный env/auth-контракт приложения не менялся. Подробный запуск — в [LOCAL_ACCEPTANCE.md](LOCAL_ACCEPTANCE.md).
