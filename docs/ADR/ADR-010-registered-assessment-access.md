# ADR-010: анкеты доступны после регистрации

Дата: 2026-09-10. Статус: принято по прямому уточнению владельца.

## Решение и пользовательский путь

«Бета» обозначает стадию тестирования приложения. Владелец потребовал полностью доступный зарегистрированным пользователям контур без ручного приглашения каждого человека. Это заменяет прежнее требование invite-only/OFF-by-default из задания закрытой беты. Исторические acceptance/release-gate JSON не переписываются и не являются текущим контрактом публичного доступа.

Режим по умолчанию — REGISTERED. Существующий либо новый вошедший аккаунт получает ELIGIBLE и самостоятельно сохраняет один экран актуальных условий, совершеннолетия и настроек. Затем доступны формы трёх реализованных тем, раздельные результаты, история, практики, условия, знакомства и работа пары. Поиск и обмен с текущим партнёром включаются собственным явным выбором; общие договорённости подтверждают оба участника. Пропуски и неизвестные показатели не превращаются в уровни.

Главное меню и профиль ведут в `/questionnaires`: новые формы показаны первыми, прежние короткие анкеты и результаты находятся в отдельном свёрнутом разделе. Завершение прежнего onboarding предлагает прямой переход к анкетам. Существующие User, SessionSubject, пары, legacy FINALIZED и ответы не удаляются и не пересоздаются. Перепрохождение старой регистрации не требуется.

## Доступ и совместимость

GET settings не создаёт участие и не включает обработку; POST register привязан к действующей серверной сессии/intent и создаёт отдельный AssessmentParticipant с environment REGISTERED. Синтетическая запись не переносится в реальные аккаунты. Новые terms/information версии отражают изменение режима; для прежних версий нужен явный актуальный выбор. Отзыв сохраняется до нового действия владельца, повторное чтение/вход не включает права. Поздний старый запрос не восстанавливает отозванный доступ. Новые участники не получают sharing автоматически.

DTO расширен режимом REGISTERED и admission ELIGIBLE. Enum environment модели расширен значением REGISTERED; поля старых документов совместимы. Бизнес-расчёт, рубрики, каталоги и форматы ответов не меняются. OFF, остановка отдельной публикации/операции и запрет чтения несверенного восстановления сохраняются. Явные SYNTHETIC и PRIVATE_BETA поддерживаются для существующих тестов/операторских установок; отсутствие переменной больше не означает OFF.

## Работа на текущем хостинге

Достаточны действующие MongoDB replica set и session secret. При первом обращении обычного аккаунта приложение создаёт additive indexes и control record для новой установки. Существующие stoppedEffects и recoveryReconciled=false не сбрасываются. Найденные assessment participants без control record не объявляются автоматически восстановленными.

Результат финализации и чтения восстанавливается существующим materializer. Дополнительно успешные assessment HTTP-запросы выполняют ограниченный проход очереди/напоминаний/очистки не чаще раза в минуту по общей DB lease. Inbox создаёт наступившие личные напоминания при чтении и повторно проверяет права. Так работающий Vercel не требует постоянно запущенного Node-процесса для обычного пользовательского сценария. Без трафика точное фоновое расписание требует существующего worker/scheduler; система не обещает push или фоновое выполнение при полном отсутствии запросов.

При отсутствии отдельной recovery DB отзыв и удаление REGISTERED записываются в журнал основной БД с HMAC от существующего session secret. Это долговременная запись обычного контура, не независимое disaster recovery. При настроенной отдельной recovery DB ошибки её доступности не игнорируются. Restore-инструменты прежнего operator режима по-прежнему требуют отдельный ledger и не открывают несверенную копию. Потерю основной БД нельзя восстановить из её же журнала.

## Проверки

- `node --import tsx scripts/assessment-registered.integration.ts --mongod=<PATH>`: новые и существующие аккаунты без приглашений, реальные HTTP/session/origin guards, новая форма и профиль, отдельные права, отзыв, остановка и восстановление.
- `node --import tsx scripts/registered-assessment-ui.selfcheck.ts`: основная навигация и доступные состояния интерфейса.
- Обычные typecheck/lint/build и сохранённые synthetic regression suites проверяются на итоговом дереве. Статусы выполнения фиксируются в отчёте задачи, а не выводятся из наличия файлов.
