# Общие элементы интерфейса — 2026-09-07

Реализованы этапы контраста, общих состояний и общего диалога из [плана UX/UI](UX_UI_IMPLEMENTATION_PLAN.md). Классификация `FEATURE_CHANGE`. HTTP/DTO, session/ownership, модель БД, consent и обработка обратной связи не изменены. Новых зависимостей нет.

## Действия, поверхности и текст

В [globals.css](../src/app/globals.css) сохранена тёплая палитра, но активные primary/danger/success используют более тёмный фон. Spark использует тёмный текст. У описаний плиток снята прозрачность. Проверка `npm run selfcheck:ui-contrast` читает реальные CSS-токены и цвета, рассчитывает sRGB contrast для каждого stop и 101 промежуточной точки каждого градиентного перехода.

| Элемент | Минимальный contrast default | Минимальный contrast hover |
| --- | --- | --- |
| Primary | 5,407:1 | 6,360:1 |
| Secondary | 9,545:1 | 8,911:1 |
| Danger | 5,883:1 | 6,941:1 |
| Success | 5,566:1 | 6,751:1 |
| Spark | 4,968:1 | тот же базовый градиент |
| Остальные плитки | от 5,550:1 | тот же базовый градиент |
| Muted на пяти основных поверхностях | от 5,222:1 | — |
| Ссылки на пяти основных поверхностях | от 5,894:1 | — |

Это расчёт непрозрачных CSS-пар, не сертификат всей страницы WCAG. У светлых декоративных слоёв плиток тёмный foreground; они не ухудшают контраст базового градиента. Полупрозрачные неактивные controls исключены из численного критерия. Rendered states и пользовательские переопределения проверяются отдельно в браузере.

Кнопки и оформленные как кнопки ссылки используют те же `.app-btn-*`, сохраняя native button/Link. Минимальный размер — 44 CSS px, строки переносятся; общий BackBar также имеет 44 px touch target. Hover не меняет disabled/aria-disabled controls. Нажатие/выбор различимы дополнительной внутренней рамкой; focus-visible имеет непрозрачный внешний контур и светлый внутренний зазор. Для `aria-disabled` блокировку действия обеспечивает потребитель; сам CSS не заменяет семантику.

Для рабочих заголовков введён `.app-heading` (sans), для текстового статуса — `.app-status`. Декоративные шрифты доступны для крупных акцентов. Existing LoadingView/EmptyStateView сохранены: короткие пояснения пустого состояния больше не получают рукописный шрифт, вложенный spinner скрыт от screen reader, когда родитель уже сообщает загрузку. ErrorView сохраняет различие auth/rate-limit/error и callbacks retry/auth-required.

## Движение

Плитки имеют статический градиент; бесконечное `app-gradient-breathe` и неработавший `background-size` удалены. `app-reveal` — только opacity, 200 ms, без записи в transform; после входа hover свободно управляет transform. Локальный motion-пилот общего диалога — появление через opacity за 180 ms, без перемещений и exit-анимации. При `prefers-reduced-motion: reduce` нет анимации, переходов и hover-перемещения. Доступность действий и удаление приватного узла не зависят от завершения анимации. Motion/GSAP не добавлялись: для этого сценария достаточно CSS, дополнительный JS bundle отсутствует.

## Общий диалог и пилот CheckIn

[Dialog.tsx](../src/components/ui/Dialog.tsx) принимает `open`, `onClose`, `title`, `description?`, `busy?`, `children`, `footer?`, `className?`, `closeLabel?`, `fallbackFocusRef?`. `app-dialog-wide` расширяет окно до 52 rem, обычный максимум — 36 rem. Native `<dialog>.showModal()` помещает окно в top layer и делает фон inert. Потребитель владеет состоянием `open` и может подтвердить отказ от черновика перед фактическим закрытием.

- Заголовок получает первоначальный фокус; Tab/Shift+Tab остаются внутри видимых доступных controls. После закрытия фокус возвращается к сохранившемуся trigger. Если действие удалило trigger, потребитель задаёт явный `fallbackFocusRef`: после отправки интереса и удаления карточки из ленты MatchingFeedPage возвращает фокус к заголовку ленты. Этот случай и приоритет сохранившегося trigger проверены selfcheck; произвольный поиск другого элемента по всему документу не используется.
- Escape и X вызывают `onClose` только вне `busy`. Клик на backdrop не закрывает форму. Mutation/disabled на кнопках footer остаются ответственностью потребителя.
- Вложенный диалог подтверждения не перехватывается родителем; reference counter блокировки прокрутки восстанавливает исходный body overflow только после закрытия последнего окна.
- Header/footer находятся вне единственной прокрутки содержимого. Высота ограничена `100dvh` и safe-area margins, без таймеров и callbacks анимации.
- [CheckInModal](../src/components/activities/CheckInModal.tsx) использует этот компонент, сохраняет in-memory answers по id активности и явный consent. Отмена с неотправленными ответами требует отдельного подтверждения; pendingComplete сохраняет существующее безопасное повторение завершающего действия. Пояснение недоступной отправки находится рядом с формой.

## Проверки и границы доказательств

`npm run selfcheck:dialog` исполняет actual component через минимальный React/DOM adapter: первоначальный/возвратный фокус, Tab в обе стороны, исключение hidden/disabled, pending Escape, controlled close, вложенное окно, восстановление исходной прокрутки. Это не эмуляция accessibility tree браузера. `npm run selfcheck:ui-contrast` проверяет цвета, включая промежуточные точки градиентов. Оба проходят локально.

Targeted ESLint общих компонентов и CheckInModal проходит. Полные types/build/agent checks и browser smoke регистрируются в общей [приёмке UX/UI](UX_UI_ACCEPTANCE.md), чтобы не выдавать проверки отдельного компонента за приёмку всей поставки. Baseline: [главная 390 px](evidence/ux-ui-2026-09-07/before-home-390.png); в браузере до изменения подтверждены `animation-name: app-gradient-breathe` и `background-size: auto`.

CSS использует стандартные `env(safe-area-inset-*)` с существующими fallback. Установленные типы Discord SDK не предоставляют отдельный проверенный safe-area API; SDK не обновлялся. Реальная Discord desktop/Android/iOS acceptance и вывод конкретного screen reader требуют соответствующей среды и не подменяются синтетическими checks.
