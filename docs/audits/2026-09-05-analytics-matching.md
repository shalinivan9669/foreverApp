## Зависимости для будущей миграции аналитики и matching

```text
Registry: domains → dimensions → factor semantics/value schema
  → measurement/instrument bindings + aggregation + strategies + display/privacy policy
  → evidence versions/hash → immutable snapshots + effective intervals

Onboarding / weekly / activity feedback
  → purpose/capture-policy-selected Evidence
  → OWNER_PROFILE or PAIR_MODEL snapshots
  → owner cards / personal-today fallback OR pair evaluation / recommendations

Matching card actual answers
  → purpose=MATCHING Evidence → unpaired MATCHING snapshots
  + latest factor-scoped MatchingUseGrant
  + private PartnerPreferenceProfile revision
  → MatchingActualProfile → eligibility + directional/mutual evaluation
  → persisted MatchingEvaluationSnapshot
  → feed session + expiring revision-bound CandidatePresentationGrant
  → qualitative DTO → candidate UI → Like with frozen card questions/answers
  → MatchingConnection → two confirmations → PairMembershipClaim / Pair

PersonalDailyCheckIn → mutable personal-today computed block → owner dashboard
  (прямой источник Matching/Factor Evidence в проверенной цепочке не найден)
```

При изменении определения фактора затрагиваются hashes registry, evidence/snapshot versions, effective windows, matching actual/preference revisions, feed/grant validity, qualitative display и tests. Изменение только названия в UI не обязательно затрагивает всё это. Расширение purpose из OWNER_PROFILE в MATCHING требует отдельного согласия и правил источников; grant не разрешает показывать raw value кандидату. Pair-context данные нельзя автоматически переносить в unpaired matching или новую Pair.

Изменение questions[2]→questions[3] затрагивает минимум MatchingProfile, Like/CardSnapshot/RecipientResponse, Zod schemas, DTO/normalizers, forms/hooks, frozen request snapshots, existing data и integration fixtures. Нужен отдельный контракт/план совместимости. Реакции на условия — иной пользовательский смысл, их нельзя получить переименованием трёх текущих чекбоксов.

## Безопасные проверки и ограничения

- `npm run selfcheck:matching-factor-policy`: registry v6/v7, policy/hash validation, семь matching-факторов; без БД/сети.
- `npm run selfcheck:user-profile-summary`: DTO projection на синтетических owner/peer fixtures; без БД/сети.
- `npm run selfcheck:matching-disclosure`: normalizers/transport на synthetic fixtures, `globalThis.fetch` заменён mock; не live API privacy-test.

Результаты запуска, если основной исполнитель их выполнит, следует читать в общем отчёте. Миграции, интеграции, production commands и загрузка `.env` не выполнялись. Для `verify:matching:code` нельзя выводить безопасность из названия: package script включает `integration:matching-intelligence`.
